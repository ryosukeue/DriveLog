# UI Specification

## 実機フィードバックによる優先仕様（2026-07-15）

この節は、後続の旧MVP記述にある単月横Swipe、Movement分類変更、詳細統計より優先する。

- Calendarは月見出し付きSectionを縦方向へ連続表示し、現在月前後5か月から開始して端で3か月ずつ遅延追加する。
- 横Swipeによる月送りは削除する。Today/選択日、記録なし日の無効化は維持する。
- Movement Calloutは読み取り専用で、分類変更Menu、保存状態、成功Haptic、専用Errorを持たない。
- Stay Calloutは「滞在として確定」「非表示」「自動判定へ戻す」を持つ。
- Day Detailは地図、距離、移動時間、開始/終了、Mediaを中心とし、詳細統計Sectionを持たない。
- 位置情報付きMediaは角丸Thumbnail Annotationとして表示し、動画Badge、Cluster、fallback、Preview遷移を持つ。位置情報なしMediaはGridだけに表示する。

## 1. 目的

この文書は、DriveLog MVPの画面構成、見た目、操作、状態表示、画面遷移、レスポンシブ対応、アクセシビリティ方針を定義する。

実装時に、画面ごとの主要レイアウト、操作方法、表示項目を独自判断で変更しない。

## 2. UI基本方針

- iOS標準UIを基本とする
- アクセントカラーは赤とする
- ダークモードは端末設定に従う
- 縦向き表示のみ対応する
- iPhone SE相当からPro Maxまで対応する
- Dynamic Typeに対応する
- タブバーは使用しない
- FABは使用しない
- 設定画面はMVPでは実装しない
- アニメーションは画面遷移や標準状態変化に必要な最小限とする
- 画面ごとに独自の操作体系を作らず、Apple標準のNavigation、Menu、Alert、Share Sheetを優先する
- 色だけに依存せず、文字、形状、アイコンでも状態を区別できるようにする

## 3. カラー

### 3.1 Accent Color

アプリのAccent Colorは赤とする。

用途：

- 選択中の日付
- 主要ボタン
- 分類変更の選択状態
- リンクまたは操作可能要素
- 重要な選択中状態

赤は削除警告専用色としても使われるため、通常のアクセント表示では過度に警告的な見た目にしない。

### 3.2 今日の日付

今日の日付はiOSカレンダーに近い青い丸で強調する。

今日かつ選択中の場合は、次の優先順位とする。

1. 選択中の赤い塗り
2. 今日であることを示す補助表示

今日表示と選択表示が完全に同じ見た目にならないようにする。

### 3.3 ダークモード

色を固定値で直接指定せず、可能な限りSemantic Colorを使用する。

使用例：

- `Color.primary`
- `Color.secondary`
- `Color(.systemBackground)`
- `Color(.secondarySystemBackground)`
- `Color(.separator)`
- Accent Color

地図上の独自表示は、ライト・ダーク双方で視認できるコントラストを確保する。

## 4. タイポグラフィ

- システムフォントを使用する
- Dynamic Typeへ対応する
- 固定フォントサイズを多用しない
- 数値は視認性を優先する
- 距離、時間、日付は桁が変化してもレイアウトが崩れないようにする

推奨：

```text
画面タイトル：Title / Large Title相当
主要数値：Title2〜Title3相当
ラベル：Footnote〜Subheadline相当
補助説明：Footnote相当
Callout本文：Body〜Subheadline相当
```

## 5. 画面構成

MVPの主要画面は次の4つとする。

```text
月間カレンダー
    ↓
日別詳細
    ↓
全画面地図
    ↓
写真・動画プレビュー
```

写真・動画プレビューは、日別詳細のグリッドからも直接開ける。

オンボーディングは初回起動または権限未設定時だけ表示する補助画面とする。

## 6. Navigation

`NavigationStack`を使用する。

基本遷移：

```text
CalendarFeature
→ DayDetailFeature
→ RouteMapFeature
→ MediaPreviewFeature
```

戻る操作はiOS標準のNavigation操作に従う。

独自の戻るボタンは原則作らない。

画面遷移はPushを基本とする。

共有画面と削除確認はModalとして表示する。

## 7. Onboarding / Permission Screen

## 7.1 目的

初回起動時に、位置情報、モーション、写真へのアクセス理由を説明する。

## 7.2 表示内容

- アプリ名
- 短いプロダクト説明
- 位置情報が必要な理由
- モーション情報が必要な理由
- 写真・動画アクセスが必要な理由
- データが端末内で処理されること
- 外部サーバーへ送信しないこと
- 権限要求を開始するボタン

## 7.3 表示順

1. 位置情報
2. モーション
3. 写真

位置情報は必要に応じて「使用中のみ」から「常に許可」へ段階的に案内する。

## 7.4 権限拒否時

権限ごとに利用不能な機能と理由を表示する。

表示例：

```text
位置情報が許可されていません
バックグラウンドで移動を記録するには、設定で位置情報を「常に許可」にしてください。
```

操作：

- 「設定を開く」
- 利用可能な機能へ進む

権限拒否だけでアプリ全体を利用不能にしない。

## 7.5 写真の限定アクセス

限定アクセスの場合は、アクセス可能な写真・動画だけを表示する。

必要に応じて、ユーザーが選択内容を変更できる標準導線を表示する。

## 8. Calendar Screen

## 8.1 目的

月単位で、移動した日と日別総移動距離を確認する。

## 8.2 画面構成

```text
Navigation Title / 月表示
月間カレンダー
```

タブバー、追加ボタン、常設設定ボタンは表示しない。

右上に常設アクションを置かない。

## 8.3 月表示

- 1か月単位
- 週の開始曜日は端末設定に従う
- ロケールは端末設定に従う
- 前月・次月は左右スワイプのみ
- 左右矢印ボタンは表示しない

## 8.4 日付セル

通常セル：

```text
日付
```

移動日：

```text
日付
距離
```

例：

```text
13
18.4km
```

### 表示項目

- 日付
- 有効移動日の総移動距離

### 表示しない項目

- 写真枚数
- 動画枚数
- 分類アイコン
- 滞在地点数
- 最高速度
- 平均速度

## 8.5 今日

今日の日付は青い円で示す。

移動の有無に関係なく表示する。

## 8.6 選択状態

移動日をタップした瞬間、選択状態を赤いAccent Colorで表示してから日別詳細へ遷移する。

移動日のみタップ可能とする。

無効移動日、未移動日、1km未満の日は日付表示だけ行い、日別詳細へ遷移しない。

## 8.7 月送り

- 左スワイプ：次月
- 右スワイプ：前月

スワイプ時は標準的なページ遷移アニメーションを使用してよい。

過度なバウンドや独自演出は使用しない。

## 8.8 ローディング

月データ取得中は、カレンダー領域中央に`ProgressView`を表示する。

前月データを表示できる場合は、既存表示を維持しつつ小さなProgressViewを重ねてもよい。

Skeleton UIは使用しない。

## 8.9 空状態

月内に有効移動日がなくてもカレンダー自体は表示する。

画面下部へ補助テキストを表示してよい。

```text
この月には移動記録がありません
```

## 8.10 エラー

月データ取得に失敗した場合：

- カレンダー枠は維持する
- 短い説明を表示する
- 「再試行」ボタンを表示する

内部エラーコードは表示しない。

## 9. Day Detail Screen

## 9.1 目的

選択日の地図、基本サマリー、詳細統計、写真・動画を確認する。

## 9.2 Navigation Bar

タイトルは選択日とする。

例：

```text
7月13日
```

右上に`Menu`を配置する。

Menu項目：

```text
この日の記録を削除
```

削除項目はDestructive Roleとする。

## 9.3 全体構成

画面全体を縦スクロール可能にする。

基本順序：

```text
地図プレビュー
基本サマリー
詳細統計
写真・動画グリッド
```

初期表示の視覚比率は概ね次とする。

```text
地図：約60%
基本サマリー：約40%
```

固定ピクセル高ではなく、端末高さとSafe Areaに応じて調整する。

小型画面で基本サマリーが押しつぶされないようにする。

## 9.4 地図プレビュー

- 画面上部へ配置する
- 当日の全経路が収まる初期表示
- 操作は制限してよい
- 地図全体をタップすると全画面地図へ遷移
- 地図内に写真・動画、滞在、区間を簡略表示してよい
- Previewでは複雑なCalloutを開かない

地図がタップ可能であることが分かるよう、右下などに拡大アイコンを表示してよい。

## 9.5 基本サマリー

表示順は固定する。

1. 総移動距離
2. 総移動時間
3. 移動開始時刻
4. 移動終了時刻
5. 写真・動画枚数
6. 代表仮分類

### レイアウト

カード形式を基本とする。

大きな数値：

- 総移動距離
- 総移動時間

補助情報：

- 開始
- 終了
- メディア枚数
- 仮分類

iPhone SE相当では1列または2列へ自然に折り返す。

Pro Maxでも横に広げすぎず、読みやすい最大幅を保つ。

## 9.6 詳細統計

基本サマリーの下へ表示する。

表示項目：

- 移動区間数
- 滞在地点数
- 総滞在時間
- 記録点数
- 除外位置点数
- 車っぽい移動時間
- 徒歩っぽい移動時間

表示しない項目：

- 日全体の平均速度
- 最高速度

区間平均速度は地図上で区間を選択したときに表示する。

## 9.7 再集計中

既存データがある場合は表示を維持する。

画面上部または地図直下へ小さなバナーを表示する。

```text
再集計中…
```

バナーには`ProgressView`を併記してよい。

再集計中に画面全体を操作不能にしない。

既存データがない場合は中央にProgressViewを表示する。

## 9.8 データなし

有効移動データがない日を直接開いた場合：

```text
この日は移動記録がありません
```

通常はカレンダーから遷移できないため、削除直後、再集計結果の変更、ディープリンクなどの例外状態として扱う。

## 9.9 写真・動画グリッド

画面最下部に表示する。

### 基本仕様

- 原則4列
- 正方形セル
- creationDate昇順
- 写真と動画を混在表示
- セル間隔は狭くする
- 横幅いっぱいに配置する

### 動画表示

動画セルには次のいずれかを重ねる。

- 再生アイコン
- 再生時間

可能なら両方表示してよい。

### 位置情報なしメディア

グリッドには表示する。

地図には表示しない。

### タップ

1件タップでMediaPreviewFeatureへ遷移する。

複数選択モードは実装しない。

### 小型画面・Dynamic Type

基本は4列を維持する。

レイアウトが破綻する場合だけ、3列への変更を許容する。

列数変更は端末モデル名ではなく、利用可能幅に基づいて決める。

## 9.10 メディア空状態

対象メディアがない場合：

```text
この日に表示できる写真や動画はありません
```

グリッド領域を空白のままにしない。

## 9.11 分類修正

移動区間の分類修正は、全画面地図上の区間Calloutから行う。

選択肢：

- 車
- 電車
- バス
- 徒歩
- その他

変更成功時は軽い触覚フィードバックを行う。

保存中は連続タップを防ぐ。

## 9.12 滞在修正

滞在地点Calloutから次を選択できる。

- 立ち寄りとして確定
- 非表示
- 自動判定へ戻す

変更成功時は軽い触覚フィードバックを行う。

## 10. Full Route Map Screen

## 10.1 目的

当日の移動区間、滞在地点、位置情報付き写真・動画を詳細に確認する。

## 10.2 表示形式

- NavigationStack内の全画面Push
- 標準地図
- 航空写真切替はMVPでは実装しない
- 地図は画面全体を使用する
- Safe AreaとNavigation Barを考慮する

## 10.3 地図操作

許可する操作：

- パン
- ピンチズーム
- ダブルタップズーム
- 現在地へ移動
- コンパス操作
- 区間選択
- 滞在地点選択
- メディア選択
- クラスタ選択

## 10.4 現在地ボタン

現在地ボタンを表示する。

推奨位置：

- 右下
- 他のCalloutやNavigation Barと重ならない位置

位置情報権限がない場合は非表示または無効化する。

## 10.5 コンパス

MapKit標準のコンパスを使用する。

独自コンパスUIは作らない。

## 10.6 移動区間ポリライン

- 移動区間ごとに別ポリライン
- タップ可能
- 選択中区間を視覚的に強調
- 非選択区間は通常表示
- タップ領域は線幅より広く確保する

分類ごとに色分けしてよいが、色だけで分類を断定させない。

初期実装では同一Accent系統でもよい。

## 10.7 区間ラベル

各区間に原則1つ表示する。

表示例：

```text
32分・18.4km
```

ラベルはポリライン上の算出済み座標へ表示する。

ラベルタップでも区間選択と同じCalloutを開く。

## 10.8 区間Callout

区間タップ時はMap上の吹き出し形式で表示する。

Bottom Sheetは使用しない。

### 表示項目

- 開始時刻
- 終了時刻
- 移動時間
- 距離
- 推定平均速度
- 仮分類
- ユーザー分類
- 分類変更操作

### 表示例

```text
10:20–11:05
45分
18.4km
平均 24.5km/h
車っぽい移動
```

### 挙動

- 1度に1つだけ表示
- 別区間タップで切替
- 地図の空白タップで閉じる
- 画面外へ出る場合は地図位置を自動調整してよい

### 分類変更

Callout内のMenuまたはButtonから分類変更を行う。

Calloutを過度に大きくしない。

必要なら詳細部分をコンパクトな縦並びにする。

## 10.9 滞在地点

- ポリラインより大きめのポイント
- 推定滞在時間を表示
- タップ可能
- 選択時は滞在Calloutを表示

表示例：

```text
8分
1時間25分
```

## 10.10 滞在Callout

Bottom SheetではなくMap上の吹き出し形式とする。

### 表示項目

- 到着推定時刻
- 出発推定時刻
- 推定滞在時間
- 判定信頼度
- 自動判定状態
- ユーザー修正操作

### 操作

- 立ち寄りとして確定
- 非表示
- 自動判定へ戻す

非表示を選択した場合、Calloutを閉じ、地図から対象ポイントを消す。

## 10.11 写真・動画アノテーション

位置情報付きメディアだけを表示する。

表示形式：

- 正方形または角丸サムネイル
- 動画は再生アイコンを重ねる
- タップでMediaPreviewFeatureへ遷移

位置情報なしメディアは表示しない。

## 10.12 クラスタ

ズームアウト時にメディアが密集する場合だけクラスタ表示する。

ズームイン時は個別表示へ戻す。

クラスタ表示：

- 件数
- 代表サムネイルまたは標準クラスタ表示

クラスタタップ：

- その範囲へズーム
- 十分に拡大済みなら含まれるメディア一覧を表示してよい

MVPでは基本的にズーム動作を優先する。

## 10.13 Callout競合

区間、滞在、メディアのCalloutは同時に複数表示しない。

優先順位は、最後にタップした対象とする。

## 11. Media Preview Screen

## 11.1 目的

写真または動画を1件ずつ全画面で確認し、共有する。

## 11.2 表示

- 全画面プレビュー
- 黒またはシステム背景
- 撮影日時
- 位置情報がある場合は位置情報の有無を示す
- 共有ボタン

詳細な住所逆引きはMVPでは行わない。

## 11.3 写真

- アスペクト比を維持
- 画面内へ収める
- ピンチズームを実装してよい
- ダブルタップズームは任意

## 11.4 動画

- AVPlayerによる再生
- 標準再生コントロール
- 再生、一時停止、シーク
- 画面遷移時に不要な再生を停止する

独自動画プレイヤーUIは作らない。

## 11.5 共有

Navigation Barまたは下部に標準Shareアイコンを配置する。

タップでiOS標準共有シートを開く。

共有対象は1件のみ。

複数選択は実装しない。

## 11.6 削除済み・参照不能

PhotoKit側で削除済み、または限定アクセスから外れた場合：

```text
この写真または動画を読み込めません
```

クラッシュしない。

共有ボタンは無効化する。

## 11.7 ローディング

写真・動画取得中は中央にProgressViewを表示する。

## 12. 日付削除

## 12.1 導線

日別詳細画面右上のMenuから実行する。

Menu項目：

```text
この日の記録を削除
```

Destructive表示とする。

## 12.2 確認ダイアログ

削除前に必ず確認する。

タイトル例：

```text
この日の記録を削除しますか？
```

説明例：

```text
位置情報、移動区間、滞在地点、分類修正が削除されます。
写真アプリ内の写真や動画は削除されません。
この操作は取り消せません。
```

ボタン：

- キャンセル
- 削除

## 12.3 削除中

- ProgressViewを表示
- 削除操作を連続実行できないようにする
- 画面全体を必要以上にロックしない

## 12.4 削除成功

- 軽い触覚フィードバック
- 日別詳細を閉じる
- カレンダーへ戻る
- 該当日の距離表示を消す

## 12.5 削除失敗

- 日別詳細を維持する
- 短いエラーAlertを表示する
- 再試行可能にする
- 部分削除状態をUIへ見せない

## 13. 状態表示

## 13.1 Loading

基本は`ProgressView`を使用する。

Skeleton UIは使用しない。

## 13.2 Refreshing / Reprocessing

既存データを維持し、小さなバナーで表示する。

```text
再集計中…
```

## 13.3 Empty

各画面で明示的な空状態を表示する。

例：

```text
この月には移動記録がありません
この日は移動記録がありません
この日に表示できる写真や動画はありません
```

## 13.4 Error

- 短い説明
- 必要なら再試行ボタン
- 内部エラーコードは非表示
- 権限エラーは設定アプリ導線を表示

## 13.5 Offline

外部サーバーを使用しないため、通常機能にネットワーク接続は不要。

PhotoKit資産がiCloud上にのみ存在し、取得に通信が必要な場合は、読み込み失敗として扱い、再試行できるようにする。

## 14. Haptic Feedback

触覚フィードバックは次の場合だけ使用する。

- 分類変更成功
- 滞在修正成功
- 日付削除成功
- 保存を伴う明確なユーザー操作成功

通常の画面遷移、スクロール、カレンダー月送りでは使用しない。

エラー時の強い触覚は、破壊的操作失敗など必要な場合だけ使用する。

## 15. Animation

許可するアニメーション：

- Navigation標準遷移
- カレンダー月送り
- Callout表示・非表示
- クラスタ展開
- バナー表示・非表示
- 削除後の画面更新

禁止：

- 長いイントロアニメーション
- 自動再生する装飾アニメーション
- 大きなParallax
- 情報確認を妨げる連続アニメーション

Reduce Motion設定を尊重する。

## 16. レスポンシブ対応

## 16.1 対象

- iPhone SE相当
- 標準サイズiPhone
- iPhone 15
- Pro Max相当

## 16.2 基本方針

端末モデル名で分岐せず、利用可能幅、高さ、Safe Area、Dynamic Typeでレイアウトを決める。

## 16.3 小型画面

- サマリー項目を縦または2列で表示
- Callout幅を画面内へ収める
- 地図の最低高を確保する
- メディアグリッドは必要なら3列へ変更
- Navigation Titleが切れないようにする

## 16.4 大型画面

- コンテンツを無制限に横へ伸ばさない
- サマリーカードは読みやすい最大幅を保つ
- 地図は横幅いっぱいでよい
- グリッドは原則4列を維持する

## 16.5 横向き

MVPでは対応しない。

アプリのInterface OrientationをPortraitへ制限する。

## 17. Dynamic Type

- TextはDynamic Type対応スタイルを使用する
- 固定高さのText領域を避ける
- 文字拡大時に切り捨てない
- Calloutが画面を埋める場合は内容を簡略化またはスクロール可能にする
- 重要数値は1行を優先するが、必要なら縮小ではなく折返しを選ぶ
- グリッド列数は表示幅に応じて調整可能とする

## 18. アクセシビリティ

### 18.1 VoiceOver

各操作要素に意味のあるLabelを付ける。

例：

```text
「7月13日、移動距離18.4キロメートル」
「移動区間、10時20分から11時05分、18.4キロメートル」
「滞在地点、推定1時間25分」
「動画、7月13日14時30分撮影」
```

### 18.2 タップ領域

操作可能領域は原則44pt以上を確保する。

ポリラインは見た目の線幅より広いタップ判定領域を持たせる。

### 18.3 色覚

分類や選択状態を色だけで表現しない。

文字、線種、選択状態、アイコンを併用する。

### 18.4 Contrast

ライト・ダーク両方で十分なコントラストを確保する。

## 19. 画面別ViewModel責務

## 19.1 CalendarViewModel

行うこと：

- 月データ取得
- 月送り状態管理
- ローディング、空、エラー状態管理
- 日付選択可能判定
- 日別詳細遷移データ生成

行わないこと：

- SwiftData直接操作
- 日別距離計算
- Calendarの週開始曜日独自決定

## 19.2 DayDetailViewModel

行うこと：

- 日別詳細取得
- 再集計状態表示
- メディア一覧管理
- 削除UseCase呼び出し
- エラー状態管理

行わないこと：

- ポリライン生成
- PhotoKit直接操作
- 区間分類ロジック
- 滞在判定

## 19.3 RouteMapViewModel

行うこと：

- MapScene保持
- 選択中区間、滞在、メディア管理
- Callout表示状態管理
- 分類・滞在修正UseCase呼び出し

行わないこと：

- SwiftData直接取得
- 区間分割
- ラベル位置計算
- PhotoKit検索

## 19.4 MediaPreviewViewModel

行うこと：

- 写真・動画読込
- ローディング、失敗状態管理
- 共有UseCase呼び出し
- 動画再生用アセット管理

行わないこと：

- PhotoKit API直接呼び出し
- 共有用一時ファイル管理
- メディア削除

## 20. UI状態モデル

各画面は最低限、次の状態を明示的に扱う。

```swift
enum ViewLoadState<Value> {
    case idle
    case loading
    case loaded(Value)
    case empty
    case failed(UserFacingError)
}
```

再集計中は`loaded`と独立した補助状態とする。

```swift
let isReprocessing: Bool
```

既存データがある再集計を`loading`へ戻さない。

## 21. Callout実装方針

区間と滞在地点は、Map上の吹き出し形式を使用する。

要件：

- 1つだけ表示
- 対象座標へ関連付く
- 画面外へはみ出す場合は地図を調整
- タップ可能な操作を含められる
- Dynamic Typeで破綻しない
- MapKit標準Calloutで不足する場合はカスタムAnnotation Viewを使用する

写真・動画は、タップ後すぐプレビューへ遷移し、詳細Calloutを必須としない。

## 22. UIテスト用識別子

主要要素にはAccessibility Identifierを付与する。

例：

```text
calendar.month
calendar.day.<localDateKey>
dayDetail.mapPreview
dayDetail.summary
dayDetail.mediaGrid
dayDetail.deleteMenu
routeMap.map
routeMap.currentLocationButton
routeMap.movementCallout
routeMap.stayCallout
mediaPreview.content
mediaPreview.shareButton
permission.openSettingsButton
```

日付やIDを含む識別子は、テストで安定して生成できる形式にする。
